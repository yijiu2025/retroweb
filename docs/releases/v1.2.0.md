# v1.2.0 —— 新建项目支持 CAS 号，物质查询可选 ChemIndex

「新建项目」的输入框现在除了粘贴结构式，还支持 **CAS 号**，
并且物质查询可以**在 PubChem 与 ChemIndex 之间切换**。

---

## ✨ 新增：CAS 号输入

在原来那个输入框里直接填 CAS 号即可，**不用切换模式**：

```
50-78-2
```

识别到后会立刻提示「识别为 CAS 号 50-78-2，点『解析结构』按它查」——
不会让你以为程序没认出来。点按钮后查结构、设为目标，与粘贴结构式走**完全同一条链路**，
分子式/分子量/原子数都由前端 RDKit 统一算 ⇒ 界面表现与粘贴结构式一致。

容忍各种写法：`CAS 50-78-2`、`cas-50-78-2`、`50 78 2`、全角连字符 `50－78－2`。

校验位抄错时**只提示不拦下**（显示「校验位可能抄错了」）——
上游认不认这个号才是权威结论，用户末位笔误也不该连查都不能查。

---

## ✨ 新增：数据源可切换（PubChem / ChemIndex）

输入框下方多了一个下拉，选哪个库。选择**存在 localStorage**，设一次长期生效。

| | PubChem | ChemIndex |
|---|---|---|
| CAS → 结构 | ✅ | ✅ |
| 中文名 → 结构 | ✅ | ❌（只认英文名） |
| 熔点 / 沸点 / 闪点 / 溶解度 | 部分 | ✅ 齐全 |
| 危害符号 / 风险代码 / 安全说明 | ✅ | ✅ |

默认 **PubChem**（覆盖最广、中文名也能查）。查 ChemIndex 时，
如果它给了熔点之类，提示行会顺带露一小条 —— 那是它相对 PubChem 的独有价值。

下拉旁边有一句话说明当前源擅长什么，不用记。

## 🔴 为什么查询改成了走后端

CAS 查询原本是前端直连 PubChem（它有 CORS 头，能直连）。
要接入 ChemIndex 时发现两道**前端过不去**的坎：

1. **ChemIndex 没有 CORS 头** ⇒ 浏览器 `fetch` 直接被拒；
2. **它有 JS 反爬挑战** —— 首次请求返回一段「安全检查」页，
   要把响应里的值写进 `HW_CHECK` cookie 再重发。纯 HTTP 客户端拿不到。

⇒ 只能由后端代理。PubChem 本来能直连，但为了让两个源**共用一个入口**、
前端不必维护两套分支逻辑，也一并走了后端。
代价是一次本机 HTTP 往返（毫秒级）。

**新增接口**：`POST /api/substance`，详见后端 v1.2.0 发布说明。

## 🐛 修复

- **CAS 校验位算法**：此前按通行文章的「隔位×2」实现，
  用 17 个真实 CAS 号一测**只有 6/17 通过**。
  正确算法是**权重递增**（从右往左 ×1、×2、×3、×4…）。
  验算水的 `7732-18-5`：`8×1+1×2+2×3+3×4+7×5+7×6 = 105`，`105 % 10 = 5` ✓
  修正后 17/17 通过、负例 3/3 正确拦截。
- **打开画板带不出 CAS 对应的结构**：输入 CAS 号后点「编辑结构式」会得到一张空画板，
  现在会先查出结构再带进去。
- 全角连字符（`－` `–` `—` 等 5 种）此前没被归一化，从 PDF / 网页复制的 CAS 号认不出来。

## ⚠️ 需要后端配合
